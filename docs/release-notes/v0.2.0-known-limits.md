# ORBIT v0.2.0: known limits

These are limits of the simulated UE in v0.2.0 that a core under test can
notice. [USAGE.md](../USAGE.md#ue-lifecycle) lists them with the rest of the
UE's NAS support.

- **Configuration Update Command between procedures.** A registered UE's
  downlink is read only while one of its procedures waits for a message. A
  CONFIGURATION UPDATE COMMAND that arrives while the UE is between
  procedures is not read until the UE's next procedure: an N2 handover then
  processes it and sends a CONFIGURATION UPDATE COMPLETE the command asks
  for late; any other procedure skips or discards it unanswered. The AMF may
  retransmit the command on T3555 meanwhile.
- **"Registration requested" is recorded, not performed.** The UE has no
  registration procedure for mobility and periodic registration update. A
  CONFIGURATION UPDATE COMMAND with "registration requested" set is still
  acknowledged when it asks for that, but the UE starts no registration and
  stays registered as it was. `orbit serve` logs a warning, and the engine
  records the request on the session (`Session.RegistrationUpdateRequested`)
  and on an attach's result.
